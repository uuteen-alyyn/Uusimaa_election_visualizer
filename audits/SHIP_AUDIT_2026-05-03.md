## 1. Type consistency across the data flow

The five types from `src/types/elections.ts` flow:
`PxWeb client → loaders → normalizer → fixture JSON → LocalFixtureSource → React components`.

- `RegionResult` shape: produced by `scripts/build-fixtures.ts` →
  consumed by `LocalFixtureSource`, `Ledger`, `aggregateRegions`,
  `fillForRegion`, `evalFormula`. ✅ Consistent.
- `FormulaToken` discriminated union: produced by
  `FormulaComposer` → consumed by `formula.ts` evaluator,
  `share-state.ts` codec, `WorkflowBuilder`. ✅ Consistent.
- `Workflow`: produced by `BUILTIN_WORKFLOWS` + `WorkflowBuilder`
  → consumed by `WorkflowBar`, `App.applyWorkflow`,
  `loadCustomWorkflows` / `saveCustomWorkflows`. ✅ Consistent.
- `ChipFields` + `Binding` + `FormulaFraming`: closed unions
  used end-to-end. ✅ Consistent.
- `AreaLevel = "maa" | "vp" | "kunta" | "aa"`: full type defined,
  but only `"vp"` and `"kunta"` are reachable in production
  (`maa` is computed-aggregate, `aa` is out of scope for v1).
  `LocalFixtureSource.listAreas` returns `[]` for the unreachable
  levels. ✅ Documented; safe.

**No 🔴 / 🟡 / 🟢 findings.**

## 2. Error paths

Per practices: every error response should include *what went
wrong* + *how to recover*.

| Surface | What happens on failure | Severity |
|---|---|---|
| Geometry fetch fails | Big banner: "Couldn't load data: …" with the underlying message | ✅ |
| Fixture fetch fails | `LocalFixtureSource` returns null/empty; map renders crosshatch (`NODATA_FILL`) | ✅ |
| Formula evaluation error | Inline alert in `WorkflowBuilder`, Finnish text via `translateFormulaError`; Save button disabled | ✅ |
| Clipboard write fails | Toast "Kopiointi epäonnistui — kopioi osoiterivistä" | ✅ |
| SVG/PNG download fails | Toast "Lataus epäonnistui" / "Karttaa ei voitu ladata" | ✅ |
| `LocalStorage.setItem` throws (full / disabled) | Swallowed; in-memory state continues working | 🟢 — silent fail; user's session works but customs won't persist. Acceptable for personal-project scope; could surface a one-shot toast in v1.1. |
| Geometry → fixture id mismatch (region in geom but no fixture row) | `getFill → null → NODATA_FILL` (crosshatch) | ✅ |
| `npm audit` 5 moderate (esbuild dev-server CORS) | dev-only; production bundle unaffected | 🟡 (already in BACKLOG; revisit before external collaborator joins) |

**Findings:** none blocking ship. One 🟡 (already in BACKLOG), one 🟢.

## 3. Output / data-shape stability

Per practices: outputs should have predictable, schema-derivable
keys (no runtime-constructed keys).

- **Fixture JSON shape** — `FixtureFile` interface in
  `elections-source.ts`. Every key is statically declared.
  ✅ Stable.
- **Share-link payload** — base64 of JSON matching `ShareableState`.
  Field set is fixed; missing fields fall back to defaults.
  ✅ Stable + backwards-compatible (extra unknown fields ignored).
- **localStorage `vk_workflows_v1`** — array of `Workflow` objects.
  Per-workflow shape stable; `loadCustomWorkflows` strips
  prototype-era ƒ-prefix bug on read. ✅ Stable.
- **Per-region keys in `shares`** — uses **canonical party slugs**
  (`kok`, `sdp`, …) for known parties, `_<sanitized-name>` for
  others. The `_`-prefix is a stable derivation rule, not a
  runtime-constructed key per the practices warning. ✅ Stable.

## 6. Performance

### Static checks (this audit)

- **Bundle JS**: 72 KB gzipped — comfortably under any common
  page-budget threshold. Largest dep: `html-to-image` (~14 KB
  gz). React + react-dom is ~42 KB gz. Visualizer code is
  ~16 KB gz.
- **Bundle CSS**: 1.73 KB gz.
- **Geometry payload**: 52 KB gz (vp) + 160 KB gz (kunta) =
  ~80 KB gz on the wire. Loaded once on mount.
- **Fixture payload**: ~30–100 KB raw per election (gz: ~20–40 KB).
  Lazy-loaded per election; cached in-memory by `LocalFixtureSource`.
- **Total cold-start payload (country view, ek2023)**:
  HTML 1 KB + CSS 1.7 KB + JS 72 KB + geometry ~80 KB +
  ek2023.json ~30 KB ≈ **185 KB gz**. Well within Lighthouse's
  perf budget for a Finnish broadband audience.
- **Render**: single-page, no SSR. First paint depends on JS
  parse + execute. Map renders on the same tick as the first
  fixture's data resolves.

### Lighthouse — to be run before deploy

Run after deploy (or against `npm run preview`):
```
npx lighthouse http://localhost:4173 \
  --only-categories=performance \
  --form-factor=desktop \
  --view
```

Target per README: **performance score > 90**. With the bundle
size + load profile above, this is achievable. Document the
actual scores in the next entry of `Logbook.md` once Phase 5
is live.

**Status:** 🟢 — pending live measurement.

## 7. Accessibility

- ✅ `lang="fi"` on `<html>`
- ✅ Skip-to-map link for keyboard users
- ✅ Global `:focus-visible` ring (2px ink outline)
- ✅ Map: `role="application"`, `tabIndex={0}`, full keyboard
  navigation (Tab/Arrow + Enter)
- ✅ Map regions: `role="option"`, `aria-label`,
  `aria-selected`; SVG has `aria-activedescendant`
- ✅ Crumb: `<nav aria-label="Sijainti">` + `aria-current`
- ✅ Pills: `role="button"` + `aria-label` where text alone
  is ambiguous
- ✅ Toast: `role="status" aria-live="polite"`
- ✅ Color is never the sole signal — ledger always shows the
  textual value alongside the map fill
- 🟢 **Min text size**: body text is 13–14px. Small uppercase
  tracked labels (10–11px) used for chrome. Per WCAG 2.1
  context-minimum (no strict pixel requirement), acceptable
  with adequate contrast. Documented here as a deliberate
  choice.
- 🟢 **No formal screen-reader test** — manual VoiceOver/NVDA
  walkthrough deferred to v1.1.

**Findings:** 2 × 🟢 (documented), no 🔴 / 🟡.
